## Meta framing

Railkit is not a vertical product. It is the sequenced install and the in-repo rules that make a host codebase cheap and safe for every editor. Proof pressure is the **shape** (owners, size, code-first, actor-agnostic path) plus dogfood hosts — not another product’s brand or outcomes.

## Goal (cost ceiling)

On a well-shaped golden application, a strong per-developer LLM load still tends to stay inside a ~USD **200**/month Cursor-class subscription. That ceiling is an **observed shape**, not a promise that every host stays under it.

## ROI arithmetic

Hard lab proof of LLM productivity lift is not available for now. Use a **break-even floor** instead of a fixed multiplier claim:

| Input | Illustrative working number | Note |
|-------|----------------------------|------|
| Monthly LLM tool cost | ~USD **200** | Cursor-class subscription; host substitutes |
| Monthly loaded coder cost | ~USD **5–6k** | Nordic-shaped mid/senior; host substitutes |
| **Break-even lift** | ≈ **3–4%** | `tool / coder` — lower bar the project must exceed |

Any real lift above break-even pays for the tool. Railkit’s job is to keep the host shaped so that lift is not burned on situating tax, wrong-owner rework, or unbounded file loads.

### Golden-application observation (informal)

On a well-shaped host using this discipline, observed productivity is on the order of **those break-even points × ~100** — roughly **2–4× more productive, or higher**. Label as informal observation / pressure, not a study and not a guarantee for every customer.

## Hedge (even without agents)

Agents are natural-language workers. Anything that makes them cheaper and safer — reachable text, small seams, normalized owners — also helps humans and the organization. If LLM tech changes or the host declines cloud agents, the same shape still compounds for onboarding, review, and delivery. Offer stays hybrid: [offer-model.md](offer-model.md).

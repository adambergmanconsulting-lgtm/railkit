## Fast path (read first)

1. **Purpose:** pay for expert + kit so the host stops wasting AI (and human) sessions on wrong docs and loosening bars; **keep** the kit so that does not evaporate when the engagement ends. Buyer/seller value: [positioning.md — Value and purpose](positioning.md#value-and-purpose).
2. **Product:** paid **change project** (expert + kit) that leaves a transferable governing framework in the host repo ([offer-model.md](offer-model.md#you--we--exit)).
3. **Why pay for that (not more tooling):** customers already buy AI editors; lift still burns on situating tax and rework. Tool subscriptions are cheap vs labor (break-even ≈ **3–4%** in the Nordic illustration) — so the missing buy is shape + judgment, not another seat.
4. **Not a multiplier claim:** informal dogfood has looked like break-even × ~**100** (about **2–4×**, or higher). Not a study. Not a guarantee. Not a claim that buying the project equals buying Cursor.
5. **Shape detail:** [../../kit/docs/WHY.md](../../kit/docs/WHY.md). Token phases: [../consulting/change-project-qualification.md#token-spending-heuristics](../consulting/change-project-qualification.md#token-spending-heuristics).

## Break-even arithmetic (context — customer’s tool cost, not our price)

Illustrates why **their** LLM subscription is cheap relative to labor — so wasting that subscription is a real problem, and a priced transformation can clear a low bar. **Not** Railkit’s engagement fee (set per engagement).

| Input | Illustrative working number | Note |
|-------|----------------------------|------|
| Monthly LLM tool cost | ~USD **200** | Cursor-class subscription; host substitutes |
| Monthly loaded coder cost | ~USD **5–6k** | Nordic-shaped mid/senior; host substitutes |
| **Break-even lift** | ≈ **3–4%** | `tool / coder` — the floor the project must exceed |

These numbers are illustrations, not a universal salary or a promise that every host stays under ~USD **200**/mo.

You do not need a lab-proven 2× to justify the tool. You need sessions that stay on the right work long enough for a small lift to survive. What burns that lift: [../consulting/change-project-qualification.md#token-spending-heuristics](../consulting/change-project-qualification.md#token-spending-heuristics).

### Status quo cost (illustrative)

If the tool is only ~**3–4%** of loaded labor, burning a large share of that seat (and of engineer attention) on situating tax and rework is the visible leak. A priced change project targets that leak and leaves rules in git so the spend is not trapped in seats, wiki, or consultants. Not a full ROI model and not a guarantee that every host recovers a set multiple — see [usp-moat.md — Do not claim](usp-moat.md#do-not-claim). Business-owner wording: [positioning.md — For the business owner](positioning.md#for-the-business-owner).

## Why the tool alone fails (commercial)

The subscription clears break-even on paper. In practice, published results are mixed (see [External results](#external-results-tempering-only)). Teams still waste the budget when the next editor — human or agent — cannot find the deciding intent or prove the change.

That pressure is the same for agent-centric work and for any remote editor (new hire, outsourced team): **enough specifications and intent**, plus checks and tests that serve a priority rank so the repo still meets that intent. Buying Cursor (or an equivalent) does not install that. Cost of missing the one right owner doc (**situating tax**): [../consulting/change-project-qualification.md#token-spending-heuristics](../consulting/change-project-qualification.md#token-spending-heuristics).

A markdown rules dump or a one-off cleanup does not stick either: two docs both deciding the same thing return, ceilings rise under deadline, and how stays in chat.

## Why Railkit (or something like it)

Hybrid lock and You / we / exit: [offer-model.md](offer-model.md#you--we--exit). In one line: leave a transferable governing framework in git; land it with a **human expert with broad domain expertise** paired with the kit — not a rules dump and not kit-copy alone.

Without the framework, the engagement’s judgment evaporates when the consultant leaves. Without the expert, copy-merge fails on hosts that still have dual deciding docs and no deciding path.

Mechanism (goal → means → hedge): [../../kit/docs/WHY.md](../../kit/docs/WHY.md). Claims must survive [usp-moat.md — Do not claim](usp-moat.md#do-not-claim).

## Informal observation (not a study)

On a well-shaped host using this discipline, a strong per-developer LLM load has tended to stay inside a ~USD **200**/month Cursor-class subscription. Observed productivity has been on the order of the break-even points × ~**100** — roughly **2–4× more productive, or higher**. Pressure from dogfood, not a customer guarantee. Do not attach this to another product’s brand ([usp-moat.md](usp-moat.md#do-not-claim)).

## External results (tempering only)

Hard lab proof of a single LLM productivity multiplier is not available.

| Kind of result | What it shows | Use here |
|----------------|---------------|----------|
| Constrained task trial (e.g. Copilot HTTP-server RCT) | Large speed-up on a small, unfamiliar task | Tools *can* help when work is local |
| Multi-firm field trials (thousands of developers) | On the order of **~26%** more completed tasks | Lift happens; it is not 2–4× by default |
| Experienced developers on mature repos (METR 2025, Cursor-class tools) | About **19% slower**, while people *thought* they were faster | Tools can burn time when the repo is expensive to situate |
